    个性化联邦学习的第一课：从 IID 到 Non-IID，全面解析数据划分 ¶

    约 2569 个字 206 行代码 预计阅读时间 15 分钟

    在开始着手个性化联邦学习（PFL）方向时，一定会接触到几种不同的数据分区方式。这些分区方式旨在模拟联邦学习所面临的各种数据分布情景，是衡量算法性能的标尺。

    我们将从最顶层的概念——IID 与 Non-IID——开始，逐步深入探索当今研究中主流的数据划分策略。

    第一类：IID ( 独立同分布 ) 分区 ¶

    IID (Independent and Identically Distributed) 是一个理想化的假设。

    • 是什么：在这种分区下，每个客户端的数据分布都与全局数据的整体分布完全相同。简单来说，就像将一副扑克牌完美洗匀后，平均发给每个玩家，每个玩家手中的牌在统计上是相似的。
    • 如何划分：实现方式非常简单，通常是将整个数据集的所有样本随机打乱，然后平均分配给每个客户端。
    • 为何使用：虽然在现实世界中几乎不存在，但 IID 分区是联邦学习算法的“出厂测试”。一个算法首先要能在最简单的 IID 环境下有效收敛，这可以作为一个基础的健全性检查（Sanity Check）。

    既然是理想化假设，实际上各个客户端的数据分布肯定不会是如上所述的情况，而是各个客户端可能由于个人偏好、所处地区等各种原因出现各种各样的数据分布。这也是联邦学习的应用真正落地时的挑战之一。因此，越来越多的研究通过模拟数据异质的情况并尝试通过各种方式解决其带来的问题：

    第二类：Non-IID ( 非独立同分布 ) 分区 ¶

    Non-IID 是联邦学习所面临的真实困境，也是个性化联邦学习（PFL）存在的根本原因。它指的是各个客户端的数据分布各不相同。这种异构性主要可以细分为两大类：标签偏斜和特征偏移。

    2.1 标签偏斜 (Label Skew) ¶

    这是最被广泛研究的异构类型，指的是各个客户端拥有的数据类别（标签）分布不一致。

    2.1.1 病态非 IID 划分 (Pathological Non-IID) ¶

    这是一种用于创造极端异构环境的硬性划分方法，在早期研究中非常流行。

    • 如何划分：强制为每个客户端只分配少数几个类别的数据。
    • 特点：能快速制造出客户端之间类别完全不重叠或重叠极少的极端场景，非常适合测试算法的“下限”性能。

    2.1.2 狄利克雷分布划分 (Dirichlet Distribution Partitioning) ¶

    这是当前联邦学习研究中最主流、最标准的标签偏斜模拟方法。

    • 如何划分：它通过一个被称为浓度参数 α (Alpha) 的“旋钮”来控制数据在客户端之间的不均衡程度。这个α值越小，客户端之间的数据分布差异就越大，异构性就越强 。
    • 特点：相比病态划分，狄利克雷分布能生成更平滑、更真实的非 IID 场景。

    我们可以将狄利克雷分布想象成一台可以调节的机器，它的任务是为每个客户端生成一份独一无二的“数据配方”。这份配方决定了该客户端的数据集中，各个类别的样本应该占多少比例。

    • 输入：类别总数（比如 CIFAR-10 有 10 个类）和一个关键的调节旋钮——浓度参数α (Alpha)。
    • 输出：为每个客户端生成一个概率向量 p = (p₁, p₂, ..., p₁₀)，其中 p₁ + p₂ + ... + p₁₀ = 1。这个向量就是客户端的“数据配方”，p₁ 代表类别 1 的数据应占的比例，p₂ 代表类别 2 的比例，以此类推。
    关键调节旋钮：浓度参数α (Alpha) ¶

    α 是一个正数，它决定了数据异质性（Non-IID）的程度。不同论文可能会用不同的符号（如β或ε），但含义相同 。

    • 当 α 很大时 ( 趋向于 ∞)：
    • 效果：机器会生产出非常“标准和平均”的配方。每个客户端的概率向量都将非常接近 (0.1, 0.1, ..., 0.1)。
    • 结果：所有客户端的数据分布都几乎相同，每个类别都占有差不多的比例。这模拟的是数据同质化 (IID) 或接近 IID 的场景 。
    • 当 α 很小时 ( 趋向于 0)：
    • 效果：机器会生产出非常“极端和偏心”的配方。生成的概率向量会非常稀疏，即大部分概率集中在少数几个类别上。
    • 结果：每个客户端的数据集将由一个或极少数几个类别主导。例如，一个客户端可能 95% 的数据都是“猫”，另一个客户端可能 98% 的数据都是“狗”。这模拟的是数据高度异质 (Non-IID) 的场景，也是联邦学习研究中最常见的设置 。

    2.2 特征偏移 (Feature Skew) ¶

    这是一种更隐蔽但同样重要的异构类型，指的是即使客户端拥有相同的标签，这些标签对应的数据特征本身也存在系统性差异。

    目前比较常见的设置如下：

    • 旋转设置 (Rotated setting)：不同客户端的数据被施加了不同角度的旋转（如 0°, 90°, 180°, 270°）。
    • RGB&HSV 设置: 一半客户端使用标准的 RGB 三通道彩色图像，而另一半则将图像转换到了 HSV 色彩空间 。

    这种划分方式对于测试算法在面对领域偏移 (Domain Shift) 时的鲁棒性至关重要。

    狄利克雷分布数据划分和病态数据划分的代码实现解析 ¶

    参考了 PFLlib 的实现。

    具体位置在 dataset_utils.py 文件中。

    1. 狄利克雷分布数据划分（partition="dir"）¶

    核心思想：使用狄利克雷分布来控制每个客户端的数据类别分布，实现 Non-IID 数据划分。

    关键参数：

    • alpha = 0.1：狄利克雷分布的浓度参数，值越小数据分布越不均匀
    • 当 alpha 较小时，某些客户端会获得特定类别的大部分数据
    • 当 alpha 较大时，数据分布趋向于均匀

    实现步骤：

    1. 1.按类别分组：将所有数据按类别标签分组

    2. 2.狄利克雷采样：对每个类别 k，使用 np.random.dirichlet(np.repeat(alpha, num_clients)) 生成比例向量

    3. 3.比例调整：确保每个客户端的数据量不超过平均值 N/num_clients

    4. 4.数据分配：根据比例向量将该类别的数据分配给各客户端

    5. 5.重复验证：确保每个客户端至少有 least_samples 个样本

    2. 病态数据划分（partition="pat"）¶

    核心思想：每个客户端只拥有有限数量的类别数据，模拟极端的 Non-IID 场景。

    关键参数：

    • class_per_client：每个客户端拥有的类别数量（如 Cifar10 设为 2）
    • balance：是否平衡每个客户端的数据量

    实现步骤：

    1. 类别索引提取：为每个类别创建样本索引列表
    2. 客户端选择：为每个类别选择将要分配的客户端
    3. 数据量计算： - 如果balance=True：平均分配该类别的所有样本 - 如果balance=False：随机分配样本数量
    4. 数据分配：将类别数据按计算的数量分配给选定客户端
    5. 类别计数更新：减少客户端剩余可分配的类别数

    3. 扩展狄利克雷分布（partition="exdir"）¶

    这是一种改进的狄利克雷分布方法，增加了两级分配策略：

    1. 第一级：为每个客户端分配固定数量的类别标签
    2. 第二级：在分配的类别内使用狄利克雷分布进行数据分配

    4. 使用示例 ¶

    在数据集生成脚本中（如 generate_Cifar10.py），通过命令行参数控制：

    Bash
    # 使用狄利克雷分布，不平衡
python generate_Cifar10.py noniid unbalance dir

# 使用病态划分，平衡
python generate_Cifar10.py noniid balance pat

    5. 关键差异总结 ¶

    方法 特点 适用场景
    dir 每个客户端可能拥有所有类别，但比例不同 模拟标签分布偏斜的 Non-IID
    pat 每个客户端只拥有少数几个类别 模拟极端的标签缺失场景
    exdir 结合标签分配和比例控制的两级策略 更精细的 Non-IID 控制

    这些实现为联邦学习研究提供了灵活的 Non-IID 数据划分方案，能够模拟现实世界中客户端数据分布不均匀的情况。

    数据划分流程说明 ¶

    MNIST 数据集中包含 60000 个训练样本和 10000 个测试样本，总数据量为 70000。

    1. 合并 原始 MNIST 的训练集和测试集，形成一个 70,000 样本的总池。
    2. 对这个总池进行异构划分，分配给 20 个客户端。
    3. 在每个客户端内部，再按照 75% ( 训练 ) / 25% ( 测试 ) 的比例划分出各自的本地训练集和测试集。

    最终可以观察到各个客户端中训练集 / 测试集 = 75% / 25%。

    从上述输出可以看出，狄利克雷分布成功创造了高度异构的数据分布： - Client 0 和 Client 16 只拥有单一类别的数据（分别是标签 1 和标签 0） - Client 12 主要由标签 7 主导（5270 个样本），而标签 0 和 5 相对较少 - Client 4 数据量极少（仅 66 个样本），体现了数据量的不平衡

    这种分布很好地模拟了现实联邦学习场景中客户端数据的异质性。
